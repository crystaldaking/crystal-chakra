# v0.1.1 structural publication measurements

Date: 2026-08-18

Branch: `feature/16-structural-publication`

These are local release-build measurements, not portable performance claims.
The baseline is the v0.1.1 indexing-budget run recorded before structural
publication. Current and maximum RSS are best-effort macOS process samples;
the update harness runs in an isolated local clone and never edits the source
worktree.

## Reproduction

Initial index:

```text
/usr/bin/time -l env CHAKRA_LARGE_REPOSITORY=<worktree> \
  cargo test --release -p chakra-language --test large_workspace \
  large_repository_stays_within_published_budgets -- --ignored --nocapture
```

One-file revision (the harness appends a trailing comment to the first sorted
supported source in a temporary `git clone --shared` checkout):

```text
/usr/bin/time -l env CHAKRA_LARGE_REPOSITORY=<worktree> \
  cargo test --release -p chakra-language --test large_workspace \
  large_repository_one_file_revision_is_structural -- --ignored --nocapture
```

## Interpretation

- Shallow Rust/PHP composition removes the prior full combined-graph copy.
  Initial retained RSS fell about 25% on `psp-app` and 21% on Zed.
- `rpds` persistent insertion makes cold graph construction slower in this
  implementation (about 4% on `psp-app`, 27% on Zed). This is an explicit
  tradeoff, not hidden by the memory result; bulk-build optimization can be
  evaluated separately without weakening revision sharing.
- A source-only edit still performs the authoritative Git/content freshness
  scan and currently rebuilds a language symbol catalog. The graph assembly
  itself does not visit/copy all retained facts. Incremental reverse dependency
  and catalog work belongs to issue #17.
- A declaration/call change truthfully rebuilds the affected owner/caller
  contributions. `copied_edges` counts unchanged adjacency entries copied when
  a touched per-entity vector is replaced; it is exposed so high-degree cases
  cannot masquerade as zero-copy updates.
- Old snapshots remain immutable and may be retained by readers. Structural
  sharing bounds overlapping-revision payload growth to persistent-map paths,
  changed file payloads, and affected adjacency/call indexes rather than a
  second complete repository graph.
