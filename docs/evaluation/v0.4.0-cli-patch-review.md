# CLI candidate patch review — 2026-09-19

Scope: accumulated CLI fixes in `doctor.rs`,
`main.rs`, `setup.rs`, `update.rs`, and the new `tests/doctor_json.rs`.
This review does not establish real agent-client adoption or native installer

## Result

No blocking finding in this CLI patch. Release readiness remains unproven:
client-session evidence, native distribution checks and final candidate
validation are still required.

- `doctor --json` writes one JSON document; human report notices use stderr.
  Exit-status calculation does not print a second representation. The
  executable regression covers report creation, overwrite rejection/force,
  and malformed project configuration.
- Registration parsing distinguishes absent, disabled, valid local and
  invalid/remote entries. Non-string arguments are rejected instead of
  silently discarded. Parse errors use fixed reasons; raw registration
  mismatch details remain local diagnostics, as stated in command help.
- Setup/removal reject duplicate, nested and dangling managed markers.
  Removal no longer normalizes blank lines throughout user instructions.
  Existing ownership and shared-instruction-file rules remain in place.
- Update production logic is unchanged. Added controlled HTTP tests exercise
  newer/current/older/unavailable-asset/failure outcomes and persistent
  automatic-check throttling. They do not prove native installed-binary
  update discovery.

## Architecture and evidence

The patch remains in the CLI adapter. It adds no dependencies, agent execution,
background tasks, domain/query contracts or implicit setup on MCP startup.
The instruction ownership changes conform to ADR-0055.

The latest completed whole-worktree validation in `target/kmp-fix/kotlin-owner-review/`
includes these unchanged CLI source files: 919 tests passed, 31 opt-in tests
ignored, workspace Clippy/formatting/dependency policy passed. The CLI portion
