# Bounded LSP notification draining

Review date: 2026-09-19. Scope: `Client::drain_events` and its lifecycle
regression; this is not a completed review of the entire v0.4.0 candidate.

## Finding and correction

The existing drain loop stopped only when the incoming queue became empty.
A concurrently replenished queue could therefore prevent the provider owner
from checking cancellation, deadlines or shutdown, while callbacks retained
more events than the transport queue capacity. Kotlin's readiness wait uses
this same drain path.

The regression sends 256 notifications through a transport with capacity 64.
Before the fix one drain delivered all 256, failing the batch-bound assertion.
The callback deliberately takes 1 ms per notification to model event handling
while the reader replenishes the queue; this delay is not a production retry.

The client now snapshots the pending queue length at entry and dispatches at
most that many events. Later arrivals remain queued. The test verifies both
the per-call bound and eventual delivery of all 256 notifications.

## Review

Self-review and architecture review found no remaining blocker in this patch.
The owner retains the same transport, cancellation and shutdown mechanisms;
no tasks, queues, dependencies, protocol types or query surface are added.
The change enforces the existing bounded-work invariant in SPEC and AGENTS,
so it requires no new architectural decision. Its bound is an event count,
not a wall-clock guarantee for arbitrary user-provided callbacks.

Evidence is retained in `target/kmp-fix/drain-review/`, including the failing
pre-fix run. Executed in this worktree:

- `cargo test -p chakra-lsp -p chakra-provider-worker -p chakra-provider-kotlin-lsp`:
  58 passed, 11 opt-in tests ignored.
- `cargo test --workspace`: 917 passed, 31 opt-in tests ignored, exit 0.
- `cargo clippy --workspace --all-targets -- -D warnings`: passed.
- `cargo fmt --all -- --check`, `cargo deny check`, `git diff --check`: passed.

The test peer's start marker was subsequently moved before its notification
writes to avoid small-pipe deadlock on Windows; `cargo test -p chakra-lsp`
then passed all 14 tests, and crate Clippy plus workspace formatting passed.
The production source was unchanged between these checks. No native Windows
execution is claimed here.

Dogfooding with the available release binary (providers disabled) returned
successful `status`, `repo_map` and scoped `diff_context`; the latter reported
both changed LSP files with Git provenance. It supports navigation review,
not execution evidence for the rebuilt client.
No GitHub issue was created, as instructed by the maintainer.
