## Dependency review

`cargo deny check` passed advisories, bans, licenses, and sources. It reported
warning-level duplicate versions of `bitflags`, `syn`, and `windows-sys`.
Those duplicates come from the maintained upstream stacks for `lsp-types`,
`notify`, `rmcp`, `clap`, and platform support; Chakra does not select the
duplicate versions directly.

Every production dependency has a current v0.1 responsibility: atomic
publication (`arc-swap`), typed contracts/errors (`serde`, `schemars`,
`thiserror`), bounded text/syntax intelligence (`regex`, Tree-sitter Rust/PHP), native
watching (`notify`), CLI/MCP/runtime/logging (`clap`, `rmcp`, `tokio`,
`tracing`, `tracing-subscriber`), or the isolated rust-analyzer adapter
(`crossbeam-channel`, `lsp-server`, `lsp-types`, `url`, `serde_json`). No direct
production dependency was removed because the review found no unused or
unjustified entry.

The same resource review replaced post-hoc Git output length checks with
streaming bounded capture: repository discovery retains at most 64 MiB and the
worktree diff adapter at most 8 MiB while still draining child-process pipes.
Both Git paths also impose a 30-second child-process deadline. Initial and live
source reads reject a Rust or PHP file above 8 MiB or a per-language repository
source total above 256 MiB, and MCP rejects a serialized query response above 1 MiB.

## v0.1.1 caller aggregation / response-budget check

On 2026-08-18, release `chakra serve --no-rust-analyzer` was measured against
the clean Zed worktree at commit
`eb5483528be607b497afdaad0a237bebeb191249` on the same 10-core Apple M4 / 16
GiB host. An in-process stdio MCP client initialized Chakra, ran
`symbol_search("save_buffer", limit=100)`, selected the exact revision-scoped
method, and ran `context(limit=20, allow_stale)`:

| Zed symbol | Structured envelope | Complete JSON-RPC line | Candidate groups | Truncated |
| --- | ---: | ---: | ---: | --- |
| `Project::save_buffer` | 2,830 B | 2,916 B | 2 | no |
| `BufferStore::save_buffer` | 3,032 B | 3,118 B | 2 | no |
| `LocalBufferStore::save_buffer` | 7,748 B | 7,834 B | 5 | no |

The `Project::save_buffer` run, including cold syntax indexing and both
queries, completed in 7.43 s. Its complete JSON-RPC response is materially
below the earlier approximately 87 KiB observation. The response retained the
selected declaration, source, revision/freshness/provider metadata and honest
syntax candidate groups; no exact syntax callers or tests existed for that
selection, so none were invented.

A broader `callers` sample confirmed aggregation on real repeated Zed sites.
For the integration `open_buffer` target,
`tab_switcher_tests::test_close_selected_item` occupied one caller entry with
`occurrence_count=4`, three representative ranges, and one omitted range. For
`ActionLog::new`, `test_linked_action_log_independent_tracking` occupied one
entry with three occurrences and three representatives. The entries did not
consume four or three result slots respectively.

The same release binary was checked against the clean `psp-app` corpus.
`TransactionStatusService::syncStatus` produced an 8,653 B structured
envelope (8,739 B complete JSON-RPC line) with six syntax candidate groups;
the only truncation was the independently reported 20-line declaration source
budget. Startup plus symbol/context queries completed in 1.356 s.

These measurements cover retained output and end-to-end transport size.
Structured tracing records query construction time and bounded-section bytes,
typed-envelope serialization time, exact budget-walk time, and final envelope
bytes separately. Final JSON-RPC encoding remains owned by rmcp and is measured
end to end because rmcp exposes no supported per-message transport timing hook.

## v0.1.1 query work-budget check

On 2026-08-18 the optimized `chakra-engine` high-degree regression suite ran
five generated cases with 3,000 incoming edges, 3,000 repeated ambiguous call
sites, 5,000 allocation-pressure call sites, 3,000 repository files, and 3,000
symbols in one changed file. The five optimized tests completed in 0.01 s on
the 10-core Apple M4 / 16 GiB host.

With the default result limit of 20, incoming edge/call-site traversal stopped
at 2,048 visits and changed-symbol inspection stopped at 1,024 symbols. The
separate maximum-result (`limit=500`) allocation-pressure case stopped at its
formula-derived 4,000 retained intermediates. Each response carried the
matching typed section/cause; the default-limit cases retained no more than 20
result entries, and repeated identical queries returned identical data and
truncation metadata. `repo_map` returned the lexically first 20 paths and an
exact 2,980-file omission count without constructing 3,000 summaries.
