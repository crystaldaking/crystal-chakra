# v0.1.1 Indexing Budget Evaluation

This record validates issue #11 on real Rust and PHP worktrees. Measurements
are local engineering evidence, not cross-machine SLAs. No evaluated source is
copied into Chakra.

## Environment

- Date: 2026-08-18
- OS: macOS 26.6.1, Darwin 25.6.0, arm64
- CPU / memory: Apple M4, 16 GiB
- Rust: pinned workspace toolchain (`1.97.1`)
- Profile: Cargo `release`
- Chakra branch: `feature/11-indexing-budgets`

## Command

```sh
/usr/bin/time -l env CHAKRA_LARGE_REPOSITORY=/absolute/evaluated/worktree \
  cargo test --release -p chakra-language --test large_workspace \
  -- --ignored --nocapture
```

The ignored harness checks the published file/source/symbol/edge/call-site
budgets, requires all indexing phases, runs the full graph consistency audit,
publishes the graph and indexing metadata together, and executes bounded
`repo_map` and `symbol_search` queries.

## Interpretation and limits

- Phase times are measured inside Chakra; `/usr/bin/time` wraps Cargo plus the
  test process, while the maximum RSS is dominated by the test process after
  compilation was already warm.
- `current_rss_bytes` and `observed_phase_peak_rss_bytes` are best-effort
  samples, not OS high-water claims. The external maximum is recorded
  separately.
- Count and byte limits determine revision contents. Time and RSS targets only
  emit warnings, so unchanged content cannot receive a different graph merely
  because the machine was temporarily busy.
- Structural publication reuse and its before/after measurements are recorded
  in `v0.1.1-structural-publication.md`. The full generated/scheduled regression
  matrix, no-op freshness cost, cancellation, and provider measurements remain
  tracked by the other issues in #15–#21.
