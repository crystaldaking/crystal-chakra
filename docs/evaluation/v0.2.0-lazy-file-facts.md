# v0.2.0 Lazy File Facts Evaluation

This record validates issue #42 (lazy revision-scoped file facts) on a
synthetic corpus and on one real worktree. Measurements are local engineering
evidence, not cross-machine SLAs.

The fact under test is `FileOutlineDigest` (`file_outline_digest` v1): a
rendered per-file outline/signature digest derived from the syntax-indexed
graph, `Provenance::TreeSitter` / `Precision::Syntax`. "Eager" computes the
digest for every indexed file up front (what retaining this fact for the
whole revision would cost); "lazy" serves a `context`-style workload that
touches every 25th file (4%), each requested twice, through a bounded
`LazyFactStore`.

## Interpretation and limits

- Lazy computation wins under a sparse workload on both corpora: ~23× less
  wall time and ~25× less retained fact payload on the synthetic corpus, ~8×
  and ~29× on the real worktree. The win is structural, not incidental: the
  harness asserts eager performs exactly one computation per indexed file
  while lazy performs exactly one per *touched* file, with repeats served as
  cache hits. Wall times confirm the count-level claim.
- The per-file digest is deliberately cheap (a sorted render of already
  indexed symbols); the absolute eager cost is small at this repository's
  size. The case for laziness grows with file count, digest size, and
  workload sparsity — the synthetic corpus shows the scaling direction. For
  genuinely expensive facts (per-file re-parse, large-file summaries) the
  same contract bounds cost via `FactBudget` instead of eager indexing.
- The lazy path adds bounded machinery: FNV-1a content hashing per request,
  one mutex-protected map, one condvar per in-flight computation, and LRU
  eviction under count/byte bounds. Store overhead is included in the lazy
  wall time above. The retained-byte column counts fact payload estimates for
  both paths; map keys, `Arc`s, and synchronization bookkeeping are excluded.
- Coalescing, cancellation/failure non-poisoning, eviction, revision
  invalidation, and provenance honesty are covered by deterministic unit
  tests in `crates/chakra-engine/src/lazy.rs` (channel/barrier-controlled
  concurrency, no sleeps).
- Timings are single-run measurements on one machine. The deterministic
  assertions (computation counts, hits, bounds) are the CI gate; the wall
  times are the record.
