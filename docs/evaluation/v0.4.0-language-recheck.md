# v0.4.0 language recheck — 2026-09-16

This report records the initial recheck, before the follow-up Kotlin readiness
and project-scope fixes. See [the Kotlin acceptance follow-up](v0.4.0-kotlin-acceptance.md)
for current results; the failure and dependency-audit statements below are
historical evidence.

suite on macOS and Linux. Real-provider smoke tests pass for 10 languages.
PHP uses Chakra's built-in resolver and requires no external LSP. **Kotlin's
real-provider smoke test fails**, so Kotlin remains `in-progress` and
`advertised: false`.

## Kotlin failure and corrections

The existing test environment had multiple defects that prevented a valid
real-server check:

1. The adapter passed positional `stdio`; the executable requires
   `--stdio`. The Docker wrapper also prepended its own positional argument.
   The adapter now supplies exactly `--stdio`, and the wrapper forwards
   arguments unchanged. Hermetic lifecycle peers reject incorrect arguments.
2. The Kotlin smoke fixture contained a Go module declaration in a Gradle
   settings file and used `CHAKRA_GOPLS`. It now creates a valid Kotlin/Maven
   project with Kotlin plugin/stdlib 2.2.20, uses `CHAKRA_KOTLIN_LSP`, and
   checks the provider provenance and returned revision.
3. The image's final `|| true` masked failures in the Kotlin installation
   command chain. It was removed; checksum and executable checks are required.
4. The previously pinned 262.9593.0 binary exits with an expired-build
   message. The image and doctor expectation now use official 263.4702.0.
5. The replacement server invokes external `mvn` for this project. Maven
   3.9.16 was added to the test image with SHA-512 verification.

After these corrections, the real test still fails. Its source contains
`fun caller() { target() }`; the first incoming-calls query returns
`ProviderState::Ready`, revision 1, and `incoming: []`. A debug run shows
that project import is still underway at that point. A separate raw-LSP
probe waited for a successful Maven import, obtained a call-hierarchy item,
then timed out after 30 seconds requesting its incoming calls.

These observations establish a remaining readiness/compatibility failure;
they do not establish that delaying a query alone fixes it. The shared
worker's readiness policy has not been changed as part of this recheck.
No retry or sleep was added to turn the known-caller assertion into a pass.
PRECISE-02 through PRECISE-05 remain missing in the support manifest.

Reproduce the failing adapter test from the repository root:

```sh
./tools/run_lsp_tests.sh -p chakra-provider-kotlin-lsp --test real_provider -- --ignored --test-threads=1
```

Expected: the first result contains `caller`, and the second contains
`callerTwo` at revision 2 with `KotlinLsp` provenance. Observed: the first
result is empty and the test fails. Evidence: `chakra-provider-kotlin-lsp.log`,
`kotlin-probe.log` (expired old build), `kotlin263-maven-real.log`,
`kotlin263-maven-system/system/log/intellij-server.log`, and
`kotlin-direct.log`.

Self-review found no additional blocker in these test/environment fixes;
architecture review keeps language tooling at the adapter boundary and
records the updated executable contract in ADR-0056. The unresolved Kotlin
behavior and dependency gate still prevent release readiness.

## Limits and release decision

- These are bounded fixture-based checks, not exhaustive language semantics
  or all query directions. Android, Kotlin Multiplatform, and mixed-language
  precise resolution were not validated.
- Public-corpus artifacts were verified for consistency; all corpus projects
  were **not re-evaluated** in this run. Kotlin's recorded corpus results
  remain the 2026-09-13 measurements, including a hermetic provider peer.
- Provider pins and Maven are test-environment changes. No Rust dependency,
  crate boundary, graph identity, revision, or MCP contract changed.
- Kotlin's failing real-server check and the dependency audit remain open
  validation gates. No commit, issue, tag, push, or GitHub release was created
  by this recheck. The release branch remains unchanged.
