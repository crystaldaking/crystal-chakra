## Commands

RSS was independent:

```sh
/usr/bin/time -l env \
  CHAKRA_LARGE_REPOSITORY=/absolute/path/to/zed \
  CHAKRA_INDEX_WORKERS=1 \
  cargo test --locked --release -p chakra-language --test large_workspace \
  large_repository_stays_within_published_budgets -- \
  --ignored --exact --nocapture
```

## Determinism and bounds

The 1/2/8 matrix produced the same full graph fingerprint
`d6f01c1bb734c6f3` and identical coverage, capability, and degradation
snapshots. Worker completion order is removed before catalog construction by
reducing results in original lexical path order.

The parse scheduler uses an atomic cursor and no retained task queue, so
reported queue depth is zero. Each worker owns one parser and a bounded share
of results; total retained parsed work cannot exceed ADR-011's admitted
file/source budgets. Rust and PHP build sequentially under the same effective
cap. Relationship construction remains serial because it takes about 14 ms on
this corpus and owns deterministic global edge-budget allocation.

Small repositories below 32 files and ordinary live edits remain sequential.
The scheduler reserves the configured source budget before assigning a
conservative 64 MiB allowance per parser. Single-core or 64 MiB memory-target
configurations therefore resolve to one effective worker and report
`low_resource_mode: true`; the applied reserve values are present in status.
