# HEAD transition cache regression review

Date: 2026-09-18. Candidate branch: `fix/0.4.0-language-validation`.
This is local release-preparation evidence; no issue or release was published.

## Failure and contract

The previous full workspace run failed in
`head_transitions_reuse_commit_state_without_sharing_worktree_overlay`:
the first observed revision after committing a file reported `MemoryReuse`
where the test required `ColdBuild`. The original output remains in
`target/kmp-fix/compiler-review/workspace.log`.

Source inspection establishes a legitimate execution path for that result:

1. `CommitSnapshotCache::load_or_build` inserts a completed immutable commit
   report into its memory cache before returning it to the live indexer.
2. Live reconciliation builds the commit candidate before acquiring the
   publication gate and checking the watcher event epoch.
3. A changed epoch or changed verified diff discards that publication attempt.
4. The retry still needs the new commit, but now obtains `MemoryReuse` from
   the cache. It then publishes the verified composition atomically.

The failed run did not capture the exact event interleaving. The code path
above explains why its origin value is allowed; the test's universal
`ColdBuild` assertion was not guaranteed by ADR-0051. Ordinary file
reconciliation still preserves the previously published reuse record.
No cache, watcher, graph or publication implementation was changed here.

## Test correction

The test now checks the actual new commit identity and committed source bytes,
allowing either a first build or reuse after a discarded publication attempt.
It then makes a private primary-worktree edit and verifies that:

- the edit appears in the primary's effective results and overlay;
- the primary commit graph still contains only the committed source;
- the linked worktree checks out the same commit and reports `MemoryReuse`
  with a positive reused-file count;
- the linked worktree has no primary-only symbol and no dirty overlay;
- querying the linked worktree does not remove the primary's private edit.

The direct concurrent-cache test is unchanged. It still requires exactly
one `ColdBuild` and one `MemoryReuse` for two concurrent requests to a fresh
memory cache, and separately exercises disk publication. This retains the
single-builder requirement independently of watcher publication timing.
