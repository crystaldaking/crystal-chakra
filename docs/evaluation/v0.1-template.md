Use isolated fresh tasks for both runs. Keep the task brief, repository state,
model configuration, validation commands, and success criteria identical.
Counterbalance or randomize run order across a multi-task evaluation. Do not
carry discoveries or edits from the first run into the second.

enabled run, record a successful Chakra `status` result. Prefer realistic
navigation/change tasks whose outcome can be checked with tests or a focused
review, not synthetic tool demonstrations.
