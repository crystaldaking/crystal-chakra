# v0.4.0 provider lifecycle validation

Date: 2026-09-18. Scope: current working source on
`fix/0.4.0-language-validation`, based on `cb2af12`, with uncommitted changes.
This is validation evidence, not a release or immutable-candidate declaration.

## Contract reviewed

Issue #196 requires bounded, observable crash/restart assertions under
parallel workspace load, without hiding failures through sleeps, retries or
larger timeouts alone. Its current acceptance criteria were read and saved
locally in `target/kmp-fix/lifecycle-review/issue-196.json`.

The existing fixes in `111adf7` and `08c4fc8` distinguish process launches
from requests that actually trigger a crash. A cold-start failure can increase
the launch count without executing another query. Current lifecycle tests
therefore retain process counts as diagnostics and assert exactly two
crash-inducing requests: the original and one retry. The terminal query must
return `Degraded`, the provider must expose its error, and shutdown must
complete. Kotlin uses the same contract. The transport worker permits one
query retry; the handle waits on the bounded response channel. No assertion,
timeout or production behavior was changed for this validation.

An absent retry produces one recorded attempt and an extra retry produces
three, so neither satisfies the assertion. This is an inspection of the
existing test's failure conditions, not a newly executed mutation test.
Separate lifecycle tests retain cancellation, bounded waits and Unix
descendant-reaping assertions.

## Parallel repetitions

Host: macOS 27.0 ARM64, 10 logical CPUs, 16 GiB memory. Test executables were
built in the current worktree with:

```sh
cargo test --locked --workspace --no-run --message-format=json
```

The harness selected all ten `chakra-provider-*` lifecycle executables from
Cargo's JSON artifacts. It ran two parallel lanes, each with five rounds of
all ten providers. Every invocation selected exactly
`transport_crash_restarts_once_then_degrades --exact --nocapture` and had a
90-second outer process deadline. There were no failed-test reruns or sleeps
in this orchestration. Concurrently, a separate process ran
`cargo test --locked --workspace` with its ordinary test parallelism.

All **100 crash/restart invocations passed**: ten per provider across
bash-language-server, clangd, csharp-ls, gopls, jdtls, kotlin-lsp, pyright,
rust-analyzer, terraform-ls and vtsls. The workspace process was started before
the repetition lanes and was still running when both lanes completed.
This gives repeated evidence under this runner's load; it does not prove
determinism on every operating system or arbitrarily overloaded host.

Local evidence directory: `target/kmp-fix/lifecycle-review/`. `plan.json`
records providers and runner; `stress.py` is the orchestration; `stress.json`
records each command, elapsed time, exit code and log; individual `lane-*.log`
files retain assertions/output. `source-hashes.json` fingerprints 269 relevant
source/build/test files for the subsequent Docker matrix.

The concurrent full workspace run passed: **912 tests, zero failures,
30 ignored external/opt-in tests**, exit 0. `summary.json` and
